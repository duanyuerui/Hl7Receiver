# HL7 接收测试工具（WinForms / TCP / 串口）

用于快速测试迈瑞 BS 系列生化仪等设备的 HL7 v2.3.1 通讯，支持 **网口（TCP）** 和 **RS-232 串口** 两种链路，重点解决 **分包导致报文收不完整** 的问题。

默认参数：网口 `192.168.26.111:5150`，编码 `GB18030`；串口 `9600,8,N,1`，无流控。

## 运行

直接双击 `启动测试工具.bat`，或运行：

```
bin\Release\net8.0-windows\Hl7Receiver.exe
```

需要 .NET 8 Desktop Runtime（本机已安装）。修改代码后重新生成：

```
dotnet build -c Release
```

## 三种接收模式

| 模式 | 适用场景 |
| --- | --- |
| 服务端监听（仪器来连我） | 仪器主动把 ORU 结果推送到 LIS。把仪器的“LIS 地址”配置成本程序所在电脑的 IP 和端口（例如本机 `192.168.31.217:5150`）。 |
| 客户端连接（我连仪器） | 仪器作为服务端监听端口，由本程序主动连接 `192.168.26.111:5150`。 |
| 串口接收（打开 COM 口） | 仪器通过 RS-232 串口上报。本程序打开 COM 口收报文，ACK 也从同一串口回发。 |

网口默认使用“客户端连接 192.168.26.111:5150”。如果连接不上或仪器是主动上报模式，切换到“服务端监听”，并在仪器端把目标地址改成运行本程序电脑的 IP。

## 串口模式

选择“串口接收（打开 COM 口）”后，第一行会显示串口参数：

| 参数 | 说明 |
| --- | --- |
| 串口 | 下拉列出当前系统的 COM 口；USB 转串口插拔后点“刷新”。 |
| 波特率 | 可直接输入，常用 9600 / 19200 / 38400 / 115200。**必须与仪器完全一致**。 |
| 数据位 / 校验 / 停止位 | 默认 `8 / 无 / 1`，即 8N1。 |
| 流控 | 默认“无”；仪器要求硬件流控时选 `RTS/CTS`。 |
| DTR / RTS | 默认都开。部分仪器会检测 DTR/RTS 电平，拉不起来就一直不发数据。选 `RTS/CTS` 流控时 RTS 由驱动控制，此时 RTS 勾选框不生效。 |

要点：

- 串口打开失败会直接弹框（口被占用、被别的软件打开、USB 转串口驱动未装等）。
- 勾选“断线自动重连”后，串口异常断开（例如 USB 转接线被拔）会每 3 秒尝试重新打开。
- 串口和网口共用同一套 MLLP 拆包、字段解析、OBX 提取、ACK 应答逻辑；串口一次 `Read` 同样可能只收到半条报文。
- 若仪器走串口但 **不发 MLLP 的 `0x0B` / `0x1C 0x0D`**（只有 `\r` 结尾的裸 HL7），勾选“宽松拆包(空闲超时切分)”，程序会在空闲超时后把缓存作为一条报文交出。
- 串口模式下“本地自测(分片发送)”不可用：它走的是本机 TCP 监听口。串口验证可用另一台电脑/串口调试助手向该 COM 口发 MLLP 帧。

## 为什么会“接收不到完整数据”

TCP 和串口都是 **字节流**，一次 `Read` 收到的内容 **不等于** 一条完整 HL7 报文：

- 一条报文可能被拆成多次到达（本工具自测会故意拆成两片）；
- 一次到达也可能包含多条报文（粘包）；
- HL7 本身没有消息边界，必须按 MLLP 协议判断。

迈瑞 HL7 接口的 MLLP 帧格式：

```
0x0B  +  HL7 报文（MSH、PID、OBR、OBX…，每段以 0x0D 结尾）  +  0x1C 0x0D
```

本工具的处理方式：

1. 把每次收到的字节追加到该连接的缓存；
2. 找到 `0x0B` 后，一直等待，直到出现 `0x1C 0x0D` 才切出一条完整报文；
3. 剩余字节继续留在缓存，等下一批 TCP 数据补齐；
4. 粘包、半包、前置垃圾数据都能正确重组。

因此界面上显示“完整”的报文，才是真正收到 `0x1C 0x0D` 结束符的报文。

## 界面说明

- 左侧列表：最新报文在最上面。**状态 = 完整** 表示收到了完整的结束符；`不完整` 只会在开启“宽松拆包”时出现。
- **原始报文**：带 `<SB 0x0B>` / `<EB 0x1C><CR 0x0D>` 标记的完整内容。
- **十六进制**：逐字节查看，可直接确认帧头帧尾。
- **字段解析**：按段、字段展开，MSH-9（消息类型）、MSH-10（控制ID）、PID、OBR、OBX 一目了然。
- **检验结果**：把 OBX 提取成表格（项目代码、名称、结果、单位、参考范围、异常标志等）。
- **收发日志**：每次 TCP/串口分片的字节数、是否含 `0x0B`、是否含 `0x1C0D`、剩余缓存。这是排查“数据为什么不全”的关键。

日志示例（自测时的真实输出）：

```
收    215 B | 0x0B:有 0x1C0D:无 | 剩余缓存:   215 B | 0B 4D 53 48 ...
收    216 B | 0x0B:无 0x1C0D:有 | 剩余缓存:     0 B | 34 7C 73 65 ...
✔ 完整 收到报文 #1: 类型=ORU^R01 控制ID=TEST001 样本=1001 结果=3条 字节=428
```

第一片只有帧头、没有帧尾，**不能当成完整报文**；第二片补齐 `0x1C 0x0D` 后才输出完整消息。

## ACK 应答

仪器发送 `ORU^R01` 后必须收到 `ACK^R01`，否则会重发（最多 3 次）并报警。勾选“自动应答 ACK”后，工具会自动在同一个连接上回复：

```
MSH|^~\&|||||时间||ACK^R01|控制ID|P|2.3.1||||0||ASCII|||
MSA|AA|控制ID|Message accepted|||0|
```

规则：

- `ORU` → 回复 `ACK^R01`
- `QRY` → 回复 `QCK^Q02`
- `DSR` → 回复 `ACK^Q03`
- 收到的本身就是 `ACK` / `QCK` 时不回复

`AA/AE/AR` 可在界面上选择。

## 收不到数据时的排查顺序

1. 日志里有没有“已建立连接 / 串口已打开”？
   - 网口没有：IP、端口、模式不对，或仪器/防火墙阻止连接。
   - 串口没有：COM 号选错、被其他程序占用、USB 转串口驱动异常，弹框里会有具体原因。
2. 有连接但没有任何“收 xx B”：仪器没发数据，检查仪器端 HL7 上报配置和触发条件。
3. 有字节但一直显示“0x1C0D:无”、缓存不断增长：报文结束符不是 `0x1C 0x0D`，或报文确实没发完。
   - 可勾选“宽松拆包(空闲超时切分)”，设 800ms，看超时拆出来的内容。
   - 用“十六进制”确认实际结束符是 `0x1C0D`、`0x1C`、还是只有 `0x0D`。
4. 中文乱码：切换编码下拉框。HL7 标准是 ISO-8859-1，但国产设备常用 GB18030/GBK；本工具默认 GB18030。
5. 没有“自动应答 ACK”：仪器可能重发或断开，勾选自动应答。
6. 串口收不到任何字节：确认串口参数（尤其波特率、校验、停止位）与仪器完全一致；再确认 DTR/RTS 是否需要拉高，或是否需要 RTS/CTS 流控。可用串口调试助手先占用 COM 口交叉验证接线。
7. 如果十六进制里看到的是 `0x02 ... 0x03`、`<STX>/<ETX>` 或 `<ENQ>/<ACK>/<EOT>`，说明仪器当前跑的是 **ASTM E1394** 而不是 HL7，需要在仪器上切换协议，或另外做 ASTM 拆包（本工具的 MLLP 拆包不适用）。

## 自测

**网口自测**：选择“服务端监听”并开始接收后，点击 **本地自测(分片发送)**：

- 程序会向本机监听端口发送一条模拟 `ORU^R01`；
- 故意拆成两片、间隔 120ms 发送；
- 正确结果：列表出现 1 条“完整”报文，结果页有 3 条 OBX，日志显示已回复 ACK。

自测通过说明本机接收、拆包、解析、ACK 全链路正常，剩下的就是仪器侧地址/发送配置问题。

## 文件位置

- 收到的报文：`ReceivedMessages\yyyyMMdd\*.hl7`（保存的是纯 HL7 内容，不含 MLLP 三个控制字节）
- 运行日志：`Logs\yyyyMMdd.log`
- 崩溃日志：`crash.log`（如果出现）
- 界面参数：`settings.json`（关闭窗口时自动保存）
